# harness-web

Next.js control-plane UI for the hotel agent harness. Deployed on Vercel (not yet set up).

```bash
npm ci
npm run dev        # http://localhost:3000
npm run lint
npm run typecheck
npm test           # Vitest + Testing Library; Supabase and the API are mocked
npm run build
```

## Configuration

The UI reads three public variables (names in the root `.env.example`). Next.js inlines them at
build time, so set them before `npm run build`. Without them the page shows which ones are missing.

| Variable | Value |
|---|---|
| `NEXT_PUBLIC_SUPABASE_URL` | `https://<project-ref>.supabase.co`, or `http://127.0.0.1:54321` for `supabase start` |
| `NEXT_PUBLIC_SUPABASE_ANON_KEY` | The publishable key (`sb_publishable_...`) or the legacy `anon` key. The app refuses a secret or `service_role` key. |
| `NEXT_PUBLIC_HARNESS_API_URL` | The control-plane API, for example `http://localhost:8000`. Its `HARNESS_CORS_ORIGINS` must list this app's origin. |

Only `NEXT_PUBLIC_*` variables reach the browser, so never put a secret in one.
`src/lib/public-env.test.ts` fails if source code reads any other variable.

## Sign-in and the hotel switcher (DEX-13)

| Part | Code |
|---|---|
| Sign-in and sign-out (Supabase Auth, email and password, session in browser storage) | `src/lib/auth.ts`, `src/components/sign-in-form.tsx` |
| The user's hotels: the user's own `memberships` rows and the `hotels` of those orgs, read from the Supabase Data API with the user's JWT, so PR #5 RLS applies. The membership scope rule runs again in the browser. | `src/lib/hotel-directory.ts`, `src/lib/tenancy.ts` |
| API client: `Authorization: Bearer <access token>`, tenant in the path `/v1/orgs/{org_id}/hotels/{hotel_id}/...`, one 403 for every denial (`docs/auth.md`, PR #9) | `src/lib/harness-api.ts` |
| Switcher and the role check (`GET .../me`) for the chosen hotel | `src/components/hotel-switcher.tsx`, `src/components/current-hotel.tsx` |

A 401 from the API signs the user out on this device and asks them to sign in again. A 403 shows
one message, whatever the cause. The last chosen hotel is remembered per user in `localStorage`
(ids only) and is dropped when the user no longer has it.

`web/AGENTS.md` is generated by Next.js; it says to read the bundled docs in
`node_modules/next/dist/docs/` before you change framework code.
