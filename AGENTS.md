# AGENTS.md

Conventions for humans and coding agents that work in this repository.
The design authority is `docs/architecture.md`. Read the relevant section before you change an area.

## Safety rules (always)

- This repository is public. Never commit secret values, tokens, customer data, or guest data.
  Add new environment variables to `.env.example` by name only, with an empty value.
- Open PRs as drafts. Do not merge, deploy, or apply migrations to a live database without
  explicit owner approval.
- Every tenant-owned query, job, tool call, and storage path is scoped by `org_id` and `hotel_id`.
  Pass `TenantContext` explicitly; never read tenant scope from globals or tool arguments.
- Model-generated code runs only in a sandbox, never in the control-plane process.
- If you copy or adapt code from Hermes Agent (MIT), follow `THIRD_PARTY_NOTICES.md`.

## Backend (`backend/`)

- Python 3.12, uv. Add dependencies with `uv add` and commit `uv.lock`. Give each dependency an
  upper bound (`>=floor,<next_major`).
- Run before you push: `uv run ruff check . && uv run ruff format --check . && uv run mypy && uv run pytest`.
- mypy runs in strict mode. Parse input at the edge into Pydantic models or frozen dataclasses.
- New runtime adapters implement `harness.runtimes.base.AgentRuntime` and must pass the
  conformance suite (docs/architecture.md, Section 6.5). Tests never call live models.
- Tests describe behaviour contracts. Do not write tests that only restate the source code.

## Web (`web/`)

- Next.js App Router with TypeScript. Read `web/AGENTS.md` (generated by Next.js) before you
  change framework code.
- Run before you push: `npm run lint && npm run typecheck && npm run build`.
- Only `NEXT_PUBLIC_*` variables reach the browser. Never put a secret in one.

## Pull requests

- Use the PR template. Fill the safety checklist and the testing section with real commands.
- Keep PRs small and focused. One concern per PR.
- CI (`.github/workflows/ci.yml`) must be green: secret scan, backend, web, deploy config.
- Deploy config (`backend/Dockerfile`, `backend/fly*.toml`, `web/vercel.json`) is validated in CI
  and never deployed from it. Deploys follow `docs/runbook-deploy.md` with owner approval.
